# AI 真人影视互动游戏垂直切片实施计划

日期：2026-07-12
配套设计：`2026-07-12-ai-video-game-vertical-slice-design.md`
适用对象：一名主要开发者配合 AI 编码助手；视频和剧情审核由项目负责人完成。

## 1. 执行原则

- 先完成风险原型，再搭建完整模块。
- 先用占位视频打通运行时，再生成成片。
- 每个任务只改变一个明确能力，并必须附带测试。
- 任何 AI 输出都必须是结构化数据，并通过 JSON Schema 和业务校验。
- 外部服务全部通过 Provider 接口调用，运行时在线功能都有离线回退。
- 不把大视频提交到 Git；Git 只保存清单、哈希、小型样片和生成元数据。
- 不提交 API Key、Steam 密钥、签名 URL、原始玩家录音或临时生成目录。

## 2. 建议仓库结构

```text
Video/
  client/                 Unity 项目
  server/
    Api/                  ASP.NET Core API
    Worker/               生成、审核、转码任务
    Contracts/            共享数据契约
  tools/
    NarrativeCompiler/    小说到剧情包
    StoryValidator/       图、状态和媒体校验
    MediaPipeline/        清单、FFmpeg、哈希和上传
  content/
    source/               获得授权的章节文本
    story/                可审阅的结构化剧情
    manifests/            视频和生成任务清单
    samples/              小型测试资源
  tests/
    StoryFixtures/
    VoiceFixtures/
    MediaFixtures/
  docs/
```

## 3. 阶段 0：输入材料和项目约束

### VS-001 锁定首章文本

输入：一段拥有使用权的小说文本。
输出：首章范围、不可变世界事实、角色列表、地点列表和剧透边界。
验收：主路径可在 20–30 分钟完成；只包含 2 名主要 NPC、1 名敌对角色或生物、3 个地点。

### VS-002 建立内容预算

输出：节点数、意图数、视频片段数、目标总时长、在线生成次数和最大生成成本。
验收：任何新增分支都同时指出新增视频数量和成本；没有无限分支。

### VS-003 建立验收数据集

输出：200 条中文语音文本及录音计划，覆盖同义表达、口音、噪声、辱骂、离题、沉默和超长输入。
验收：每条样本都有期望意图、允许回退和禁止严重后果标记。

## 4. 阶段 1：风险原型

### VS-010 双视频播放器原型

实现两个 VideoPlayer 交替 Prepare/Play，当前视频播放时预加载下一候选视频。连续切换 100 次，记录准备时间、首帧时间、黑屏和音频中断。
验收：本地预生成分支 95% 在 300 毫秒内开始；没有可见黑屏。

### VS-011 角色一致性原型

用同一角色圣经和关键帧生成 10 段 4–8 秒视频，包括近景、半身、走动和说话。保留原始结果、采用结果、提示词、种子、模型版本和淘汰原因。
验收：至少 8 段达到 4/5 身份一致性；否则调整生产方案，不进入批量生成。

### VS-012 语音意图原型

实现在线转写、场景限定意图分类、置信度阈值和严重后果确认。
验收：在 VS-003 数据集上达到设计文档中的准确率和误伤指标。

### VS-013 云端生成闭环

客户端创建任务，服务端入队，Veo 生成，Worker 审核和转码，上传对象存储，客户端轮询并下载；准备一段本地备用视频。
验收：成功、超时、审核失败、重复请求和断网五种路径全部可测试；任何失败都播放备用视频。

## 5. 阶段 2：共享契约和剧情编译器

### VS-020 定义 JSON Schema

为 `StoryFact`、`CharacterDefinition`、`QuestDefinition`、`SceneNode`、`VoiceIntent`、`NpcResponse`、`MediaAsset` 和 `SaveGame` 建立版本化 Schema。
验收：有效样例通过；缺少 ID、引用不存在、严重后果没有确认规则等错误样例失败并返回明确路径。

### VS-021 实现剧情图校验器

检查重复 ID、悬空引用、不可达节点、无出口节点、无离线回退、任务状态不完整、媒体缺失和循环无终止条件。
验收：固定错误夹具逐一产生预期诊断；失败时进程返回非零退出码。

### VS-022 实现状态机

实现原子 `StateEffect`，支持关系值、任务状态、世界时钟、线索、位置和隐藏标记。
验收：相同初始状态和输入序列必定产生相同结果；失败或过期任务可以继续推进世界。

### VS-023 实现小说分析管线

按分段、来源引用、事实抽取、角色/地点抽取、任务候选、选择点候选、玩家意图候选、NPC 回应候选的顺序执行。
验收：每个实体保留原文引用；不确定内容标记 `needs_review`，不能自动成为不可变事实。

### VS-024 实现人工锁定流程

第一版使用可读 JSON/YAML 和命令行审阅报告，不先开发复杂后台。
验收：只有 `approved` 内容能编译成 `story.bundle.json`；锁定后生成内容哈希。

## 6. 阶段 3：Unity 离线客户端

### VS-030 初始化 Unity 项目

配置 Windows x64、固定 Unity 版本、程序集边界、测试框架、日志、统一输入系统和基础 CI 构建。
验收：干净环境可构建，编辑器测试和播放模式测试都通过。

### VS-031 剧情包加载器

实现版本检查、Schema 校验、哈希校验和友好错误页。
验收：有效包进入首节点；损坏包、版本过新和媒体缺失均有确定错误，不崩溃。

### VS-032 互动节点运行时

实现视频播放、字幕、固定选项、点击热点、节点进入/离开条件和状态效果。
验收：自动化测试遍历全部固定选项并到达至少一个结局。

### VS-033 本地存档

实现多槽位、原子写入、备份恢复、剧情版本和迁移接口。
验收：模拟写入中断不会同时破坏主存档和备份；旧版本夹具可迁移或明确拒绝。

### VS-034 影视节点地图

实现地点解锁、旅行耗时、主线/支线标记和三个探索事件入口。
验收：玩家可从视频环境进入各节点，返回后世界时间和事件状态正确。

### VS-035 影视战斗

实现 3 次以内的战术选择，例如进攻、保护 NPC、利用环境或撤退；每次选择映射到视频和状态效果。
验收：至少有胜利、代价胜利和失败后继续三种结果；失败不强制 Game Over。

## 7. 阶段 4：语音系统

### VS-040 麦克风输入

实现设备选择、权限、按住说话、最大时长、静音检测、取消和音量反馈。
验收：无麦克风、权限拒绝、设备断开和超时都能回到固定选项。

### VS-041 在线 ASR Provider

服务端代理调用 OpenAI Transcribe，客户端只上传短时音频，不接触 API Key。
验收：请求有大小、时长和频率限制；原始音频按配置删除；错误不会重复计费。

### VS-042 场景意图分类

输入只能在当前节点允许的意图集合中分类，并输出严格 JSON。
验收：未知表达进入 `irrelevant` 或 `low_confidence`，不能创建新主线或任意状态字段。

### VS-043 异常与严重后果保护

实现辱骂、威胁、离题、过长、沉默和低置信度规则。
验收：攻击、永久决裂、任务失败等严重后果需要高置信度或二次确认。

### VS-044 离线 ASR 实验

集成 whisper.cpp 的一个量化多语言模型，测量 CPU、CUDA 和 Vulkan 路径。
验收：在最低配置上给出实时系数、内存、准确率和包体报告；未达标则作为可选下载包。

## 8. 阶段 5：服务端和动态视频

### VS-050 API 基线

实现健康检查、结构化日志、请求 ID、限流、配置校验、密钥管理和统一错误格式。
验收：缺少关键配置时启动失败；日志不输出密钥、签名 URL 和原始录音。

### VS-051 生成任务状态机

状态：`created`、`queued`、`generating`、`moderating`、`transcoding`、`ready`、`failed`、`expired`。
验收：状态转移有数据库约束；Worker 重启后可继续；重复请求命中同一幂等任务。

### VS-052 Veo Provider

实现请求、长任务轮询、取消、结果下载和供应商错误映射；模型 ID 只存在服务端配置。
验收：模拟 Provider 跑完整测试；真实 Provider 只在集成环境消耗预算。

### VS-053 审核和剧情一致性

检查提示词、玩家输入、生成元数据和输出；关键视频由人工批准后才进入正式构建。
验收：违规、人物错误、台词错误和缺少来源记录均不能进入 `ready`。

### VS-054 转码和分发

实现 FFmpeg 标准化、音量检测、时长检查、哈希、GCS 上传和短期签名 URL。
验收：客户端从对象存储下载；API 不返回视频字节；损坏文件哈希验证失败。

### VS-055 成本控制

实现账号、设备、章节、每日和全项目预算；记录预估成本和实际成本。
验收：超过任一上限时不调用供应商，直接返回备用视频状态。

## 9. 阶段 6：视频资产生产

### VS-060 锁定角色和场景圣经

输出 GPT Image 2 定妆图、状态变体、场景关键帧、色彩和摄影规则。
验收：每个视频任务只能引用已批准的角色/场景版本。

### VS-061 生成镜头清单

剧情编译器输出镜头 ID、台词、时长、首尾帧、角色状态、生成档位、备用资源和成本上限。
验收：可反向追踪到剧情节点和原文；所有节点都有媒体或占位资源。

### VS-062 小批量生成和审核

每批不超过 20 个镜头；先 Fast/Lite 预览，英雄镜头再使用高质量档。
验收：每批更新采用率、平均重试次数和单位成片秒成本，未审核前不启动下一大批。

### VS-063 NPC 台词和口型

台词先锁定，语音先锁定，再生成或同步口型。
验收：人工逐条核对发音、字幕和口型；错误台词不能靠运行时换音频掩盖。

### VS-064 战斗和结局剪辑

将 4–8 秒镜头剪成 30–60 秒战斗，并建立不同策略的可复用镜头和差异镜头。
验收：三种结果在动作连续性和空间位置上成立；动态结局失败时备用剪辑叙事完整。

## 10. 阶段 7：Steam、更新和测试

### VS-070 资源拆包

至少拆分基础客户端、首章视频、中文音频字幕、可选离线 ASR。
验收：替换一个视频时不重写整个视频库；单个资源包尽量控制在 1–2 GB。

### VS-071 Steam 测试构建

接入 Steam App ID、开发分支、构建脚本和最小 Steamworks 初始化。
验收：测试账号可从 Steam 安装、离线启动、更新和回滚。

### VS-072 增量更新实验

发布 A 构建，替换一个 8 秒视频后发布 B 构建，记录下载量、磁盘临时空间和更新时间。
验收：补丁大小与修改资产规模接近；若异常，调整 Addressables 和包分组。

### VS-073 全路径自动测试

枚举固定选项和主要语音意图，执行状态机到结局。
验收：无不可达预期节点、无死路、无缺失媒体、无未处理异常。

### VS-074 封闭试玩

邀请 10–20 名玩家，记录完成率、语音使用率、误判、等待、卡顿和角色不一致反馈。
验收：至少 80% 玩家完成；严重阻断为零；形成带优先级的问题清单。

## 11. 建议时间表

- 第 1–2 周：阶段 0–1，完成风险闸门。
- 第 3–5 周：阶段 2–3，完成离线可玩灰盒。
- 第 6–7 周：阶段 4，完成语音闭环。
- 第 8–9 周：阶段 5，完成动态视频闭环。
- 第 10–12 周：阶段 6，批量生产和替换成片。
- 第 13–14 周：阶段 7，Steam 构建、补丁和封闭试玩。

如果角色连续性或口型实验未通过，时间表必须暂停在对应闸门，不能用增加生成次数假装问题已解决。
