# 《灵脉余烬》场景资产目录

本目录只服务于 [`lucifer8900/Video`](https://github.com/lucifer8900/Video.git) 的 AI 真人影视互动游戏生产。它把本机 GB18030 小说正文转化为场景事实、Unity 拆层规范和后续图像／视频提示词，不复制完整正文，也不把独立风景图当作可开发场景。

命名层：62 个 `sceneId` 保持稳定，显示名全部换成《灵脉余烬》生产名称。内部源名对照位于禁止发行的原创化映射；本轮未重绘现有 18 张场景图，因此视觉原创性仍需后续美术改造与审核。

## 当前交付

- `scene-catalog.json`：62 个按剧情推进排列的重要场景，覆盖第一卷至大结局。
- `scene-image-prompts.md`：6 个 P0 场景、每场 3 个独立资产提示词，共 18 个。
- `scene-image-manifest.json` 与 `images/p0/`：18/18 个 P0 概念资产已生成并逐张首检；文件尺寸、字节数、SHA-256 和偏差记录已固化。它们仍是待人工美术定稿的视觉圣经，不是可跳过审核的最终贴图。
- 项目视觉与玩法基线仍以 `docs/fanren/2026-07-13-fanren-game-world-bible.md` 和 `docs/superpowers/specs/2026-07-12-ai-video-game-vertical-slice-design.md` 为准。

## 场景不是一张图

每个 `sceneId` 都必须交付一个至少包含三张独立图像的场景包：

| 资产 | 内容 | Unity 用途 | 视频用途 |
|---|---|---|---|
| A 建立镜头板 | 地点轮廓、地标、尺度、前中后景、玩家动线 | 地形块面、导航和镜头锚点基线 | 开场、转场、无台词环境循环、Veo 首尾帧 |
| B 昼夜／天气变化板 | 同一机位、同一几何的晨昼暮夜和允许天气 | 天空盒、灯光、材质湿润度、雾雨雪风状态 | 时间推进、任务超时、气氛转场、备用环境循环 |
| C 模块化素材／人群活动板 | 建筑、材质、植被、水体、道具、奇观、服饰人群和循环动作 | Addressables 模块、可交互物、LOD、群体代理 | 对白背景、中近景插入、战斗细节、连续性修补 |

因此首批 6 个 P0 地点对应 18 个图像任务，而不是 6 张风景照。后续 62 个场景全部沿用同一规则。

## Unity 拆层

每个场景状态建议使用以下固定层级：

```text
L0_SkyCelestial        天空、云层、日月星辰
L1_DistantVista        远山、海平线、巨构剪影
L2_TerrainWater        地形、道路、岩土和水体
L3_ArchitectureWonders 建筑、禁制、传送阵和奇观
L4_VegetationProps     植被、药草、摊位、船只和道具
L5_CrowdCreatures      人群、修士、凡人、妖兽和环境生物
L6_WeatherVFX          雨雪雾风、沙尘、体积光和法术残留
L7_GameplayMarkers     碰撞、导航、触发区、危险区和镜头锚点
```

同一地点的战前、战中、战后不复制整张地图，而以 `sceneStateVersion` 替换损毁、封锁、人群、天气和 VFX。例如天堑城和平状态 `FR-SC-044` 与魔劫攻防 `FR-SC-053` 应复用墙体和塔群几何。

## CANON 与美术推断

`scene-catalog.json` 中每一项都包含：

- 卷／章节锚点和地点层级；
- 剧情功能；
- 地貌、植被、水体、建筑与奇观；
- 天气、昼夜、日月星辰；
- 环境危险、常驻人物／人群、可交互物；
- 色板、声音；
- `canonFacts` 和 `artInferences`。

`CANON` 是正文可追溯事实；`ART-INFERENCE` 是为摄影、Unity 和可玩性补足的可撤销设计。生成模型不能把推断升级成世界事实，也不能因为画面“更壮观”而增加正文没有的瀑布、宫殿、天体或主要人物。

特别约束：

- 尘寰界采用单日单月。
- 七曜灵陆正文明确存在七日七月的昼夜转换；天空盒必须维护统一位置、亮度和时段，不能每个镜头随机排列。
- 玄寒境、血战小界和渊魔境的具体天体如果正文证据尚未锁定，先用云、雾和环境光，不擅自发明多颗行星。
- 飞升大结局只表现界面门槛和接引天光；本书正文没有提供足够信息供本项目在此阶段创建完整仙界城市。

## 从场景板到游戏和视频

建议生产顺序：

```text
正文章节锚点
  -> 人工锁定 CANON / ART-INFERENCE
  -> 生成 A 建立板并批准几何与色板
  -> 以 A 为参考生成 B，检查建筑和地形零漂移
  -> 生成 C，拆成 Unity 模块与人群活动
  -> 建立 sceneStateVersion 和镜头锚点
  -> 写 shot-manifest / Veo 提示词
  -> 生成 4–8 秒镜头并做场景连续性审核
```

项目仍以“预生成视频为主、Unity 负责状态和分支、离线可通关”为基线。场景图是视频和 Unity 的共同视觉圣经，不表示现在要把游戏改造成自由镜头的 3D 开放世界。

## 后续验收

1. 6 个 P0 场景的 18 个资产已经生成并完成首检；下一步是人工美术批准。`FR-SC-008` 的雾门／瀑布误读和 `FR-SC-012` 的禁制、水流及守护兽表现必须在定稿前处理。
2. `scene-image-manifest.json` 已记录提示词版本、文件哈希和所属 `sceneStateVersion`；内置生成器未返回稳定任务 ID，不能伪造该字段。
3. A／B／C 需保持地点身份一致；天气变化不能引起建筑漂移，天堑城天体位置需在最终天空合成时锁定。
4. 从 `FR-SC-004`、`008`、`012` 中选择垂直切片的三个地点，制作 5–8 个无台词环境循环。
5. 正式公开或商业使用前，完成《灵脉余烬》改编授权和 AI 内容平台披露审核。
